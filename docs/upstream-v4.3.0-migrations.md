# v4.3.0 数据层升级

迁移 1–175 保留中文版现有实现；176–241 从上游 `v4.3.0`
（`77f7b3bddad5940fb9fb9de91d8ab2c53894404f`）按原顺序导入。
上游文档提供商 seed 同步导入；自驾偏好键固定为该版本的键集合，避免后续契约变化影响历史迁移。

中文版原 176 的高德身份字段和缓存改造移动至 242。启动时只对
`schema_version = 176`、存在 `places.geo_provider` 且缺少
`vacay_entries.fraction` 的旧中文库，从上游 176 开始补跑。
不直接改写存量版本号；每个普通迁移与版本更新在同一事务内提交，失败后可重试。
原有 raw 迁移仍遵循其非事务约束。

242 幂等添加身份字段，保留已有高德身份；重建缓存时复制所有行，保留
provider、语言、expanded、JSON 和时间戳，并为 provider 设置 `DEFAULT 'google'`。
省略 provider 的上游 SQL 可继续写入；高德仍必须显式指定 provider。
搜索建议的 provider 变为可选，提供时仍校验枚举。

升级前按现有运维流程备份数据库。此阶段只对齐数据层和搜索建议契约，
不代表完整 v4.3.0 服务/前端已整合。后续合并须保留迁移桥与 242，
不可用上游 runner 覆盖它们；未来上游新增迁移也须重新分配版本，不能直接拼接产生新碰撞。
迁移回归测试位于 `server/tests/unit/db/upstream-migration.test.ts`，覆盖
新安装、中文 176、上游 176/241、缓存隔离与保留、版本写入失败回滚和重复启动。
